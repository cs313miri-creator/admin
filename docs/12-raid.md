> **Из задания.** При помощи двух подключённых дисков по 1 Гб сконфигурируйте дисковый массив уровня 0. Имя устройства — `md0`, конфигурация размещается в `/etc/mdadm.conf`. Создайте раздел, отформатируйте в FAT32, обеспечьте автоматическое монтирование в `/storage`.

**Машина: HQ-SRV (105)**

### 12.0. Добавить диски в Proxmox

Выключить HQ-SRV → **Hardware → Add → Hard Disk**, размер **1** GiB → Add. Повторить второй раз. Включить машину. Диски появятся как `/dev/sdb` и `/dev/sdc`.

### 12.1. Убедиться, какие это диски

```bash
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT
```

Новые диски: размер 1G, тип `disk`, без разделов и без точки монтирования. Если у выбранного устройства есть `MOUNTPOINT` — это не тот диск. Восстановить данные после `mdadm --create` нельзя.

### 12.2. Собрать массив

```bash
apt-get install -y mdadm

mdadm --create /dev/md0 --level=0 --raid-devices=2 /dev/sdb /dev/sdc

cat /proc/mdstat
mdadm --detail /dev/md0
```

| Параметр              | Назначение                                                |
|-----------------------|-----------------------------------------------------------|
| `--level=0`           | уровень RAID; «страйп», объём и скорость без избыточности |
| `--raid-devices=2`    | число дисков в массиве                                    |

RAID 0 собирается мгновенно — синхронизировать нечего, в отличие от уровней 1 и 5.

> **Почему RAID 0, а не 5.** RAID 5 требует минимум три диска, а дано два. Из двух возможны только уровень 0 (весь объём, без защиты) и уровень 1 (зеркало, половина объёма).

### 12.3. Сохранить конфигурацию массива

```bash
mdadm --detail --scan >> /etc/mdadm.conf
cat /etc/mdadm.conf
```

Без этого после перезагрузки массив соберётся под случайным именем вида `/dev/md127`, и запись в `/etc/fstab` перестанет работать. Путь `/etc/mdadm.conf` указан в задании явно — в Debian и Ubuntu это `/etc/mdadm/mdadm.conf`.

### 12.4. Создать раздел и файловую систему

```bash
parted -s /dev/md0 mklabel msdos
parted -s /dev/md0 mkpart primary fat32 1MiB 100%
partprobe /dev/md0
lsblk /dev/md0

apt-get install -y dosfstools
mkfs.vfat -F 32 -n STORAGE /dev/md0p1
blkid /dev/md0p1
```

Раздел на массиве называется `/dev/md0**p**1` — с буквой `p` перед номером.

> **FAT32 не хранит права доступа.** `chmod` и `chown` на этом разделе не работают — команда выполнится, но ничего не изменит. Права задаются один раз опциями монтирования: `uid`, `gid`, `umask`. В задании 13 из-за этого же понадобится параметр `fsid=`.

### 12.5. Смонтировать в /storage

```bash
mkdir -p /storage

blkid /dev/md0p1    # взять UUID
echo 'UUID=XXXX-XXXX /storage vfat defaults,uid=0,gid=0,umask=000 0 0' >> /etc/fstab

mount -a
df -h /storage
```

| Поле fstab             | Значение                                                                     |
|------------------------|------------------------------------------------------------------------------|
| `UUID=...`             | что монтировать; UUID не меняется при переименовании устройства               |
| `/storage`             | куда монтировать                                                             |
| `vfat`                 | тип файловой системы                                                         |
| `umask=000`            | полный доступ всем — иначе по NFS записать не получится                      |
| `0 0`                  | без dump и без проверки при загрузке                                         |

`mount -a` после правки fstab делать обязательно: ошибка в этом файле — одна из немногих, которая не даёт системе загрузиться.

### Проверка задания 12

```bash
cat /proc/mdstat            # md0 : active raid0
df -h /storage              # около 2 ГБ
touch /storage/test && ls -l /storage && rm /storage/test
# перезагрузить и убедиться, что /storage на месте
```
