# Задание 6. GRE-туннель между офисами

**Машины:** HQ-RTR, BR-RTR

> **Контекст стенда** (нужен, чтобы команды ниже были корректны)
>
> Proxmox VE. Маршрутизаторы — **Eltex vESR 1.18**, остальное — **Альт Линукс**.
> Порты роутеров сдвинуты относительно топологии задания: **`gi1/0/2` — к ISP**, **`gi1/0/3` — внутрь офиса**
> (`net0`→`gi1/0/1` не используется, `net1`→`gi1/0/2`, `net2`→`gi1/0/3`).
> На vESR: применение — `do commit`, затем `do confirm`; на каждом интерфейсе и туннеле — `ip firewall disable`;
> удаление — повтор строки целиком с `no`. Просмотр: `show ip interfaces`, `show int status`, `show ip route`.
> В Альт: сеть в `/etc/net/ifaces/<iface>/`, применение `systemctl restart network`, пакеты через `apt-get`.
>
> Адресация: ISP `172.16.1.1/28` и `172.16.2.1/28` · HQ-RTR `172.16.1.2/28`, `192.100.100.1/25`, `192.100.200.1/26`, `192.100.30.1/29`
> · BR-RTR `172.16.2.2/28`, `192.100.20.1/28` · туннель `10.10.10.1/30` ↔ `10.10.10.2/30`
> · HQ-SRV `192.100.100.2` · HQ-CLI `192.100.200.2` · BR-SRV `192.100.20.2` · BR-CLI `192.100.20.3`
>
> Полный контекст — в [README](../README.md).

---

> **Из задания.** Между HQ-RTR и BR-RTR сконфигурируйте туннель GRE. В качестве сетевого диапазона используйте сеть `10.10.10.0/24`, для каждого туннеля используйте минимально возможную маску.

Минимально возможная маска для двух концов — `/30`: четыре адреса, минус адрес сети и broadcast, остаётся ровно два.

Не путай два набора адресов. **Внешние** `172.16.1.2` и `172.16.2.2` — их видит провайдер, они идут в `local address` и `remote address`. **Внутренние** `10.10.10.1` и `10.10.10.2` — адреса самого туннеля, по ним пойдёт OSPF.

### 6.1. HQ-RTR

```
configure

tunnel gre 1
  local address 172.16.1.2
  remote address 172.16.2.2
  ip address 10.10.10.1/30
  ip firewall disable
  enable
  exit

do commit
do confirm
```

### 6.2. BR-RTR

```
configure

tunnel gre 1
  local address 172.16.2.2
  remote address 172.16.1.2
  ip address 10.10.10.2/30
  ip firewall disable
  enable
  exit

do commit
do confirm
```

| Команда                     | Что делает                                                                      |
|-----------------------------|---------------------------------------------------------------------------------|
| `tunnel gre 1`              | создать GRE-туннель с номером 1                                                 |
| `local address`             | внешний адрес **своего** конца                                                  |
| `remote address`            | внешний адрес **чужого** конца — на второй стороне меняются местами             |
| `ip address 10.10.10.1/30`  | внутренний адрес туннеля                                                        |
| `ip firewall disable`       | туннель — тоже интерфейс; без этого он поднимется, но трафика в нём не будет    |
| `enable`                    | включить туннель                                                                |

Конфигурация зеркальная:

| Параметр         | HQ-RTR          | BR-RTR          |
|------------------|-----------------|-----------------|
| `ip address`     | `10.10.10.1/30` | `10.10.10.2/30` |
| `local address`  | `172.16.1.2`    | `172.16.2.2`    |
| `remote address` | `172.16.2.2`    | `172.16.1.2`    |

### Проверка задания 6

```
show interfaces tunnel gre 1     # Tunnel source, Tunnel destination, mode GRE, состояние up
ping 10.10.10.2                  # с HQ-RTR
```

Если туннель не поднимается, проверяй по порядку: пингуется ли `remote address` напрямую, не перепутаны ли local и remote, стоит ли `ip firewall disable`, сделан ли `enable`.
