# Задание 13. Сетевая файловая система NFS

**Машины:** HQ-SRV, HQ-CLI, BR-CLI

> **Контекст стенда** (нужен, чтобы команды ниже были корректны)
>
> Proxmox VE. Маршрутизаторы — **Eltex vESR 1.18**, остальное — **Альт Линукс**.
> Порты роутеров сдвинуты относительно топологии задания: **`gi1/0/2` — к ISP**, **`gi1/0/3` — внутрь офиса**
> (`net0`→`gi1/0/1` не используется, `net1`→`gi1/0/2`, `net2`→`gi1/0/3`).
> На vESR: применение — `do commit`, затем `do confirm`; на каждом интерфейсе и туннеле — `ip firewall disable`;
> удаление — повтор строки целиком с `no`. Просмотр: `show ip interfaces`, `show int status`, `show ip route`.
> В Альт: сеть в `/etc/net/ifaces/<iface>/`, применение `systemctl restart network`, пакеты через `apt-get`.
>
> Адресация: ISP `172.16.1.1/28` и `172.16.2.1/28` · HQ-RTR `172.16.1.2/28`, `192.100.100.1/25`, `192.100.200.1/26`, `192.100.30.1/29`
> · BR-RTR `172.16.2.2/28`, `192.100.20.1/28` · туннель `10.10.10.1/30` ↔ `10.10.10.2/30`
> · HQ-SRV `192.100.100.2` · HQ-CLI `192.100.200.2` · BR-SRV `192.100.20.2` · BR-CLI `192.100.20.3`
>
> Полный контекст — в [README](../README.md).

---

> **Из задания.** Папка общего доступа `/storage/share`, доступ для чтения и записи исключительно для сети в сторону HQ-CLI и BR-CLI. На HQ-CLI и BR-CLI настройте автомонтирование в `/srv/share`.

### 13.1. Сервер

**Машина: HQ-SRV (105)**

```bash
apt-get install -y nfs-server nfs-utils
mkdir -p /storage/share
df -h /storage/share     # устройство должно быть /dev/md0p1, а не корень

cat > /etc/exports <<'EOF'
/storage/share 192.100.200.0/26(rw,sync,no_subtree_check,no_root_squash,fsid=1) 192.100.20.0/28(rw,sync,no_subtree_check,no_root_squash,fsid=1)
EOF

exportfs -ra
exportfs -v

systemctl enable --now nfs-server
showmount -e localhost
```

| Параметр              | Назначение                                                                             |
|-----------------------|----------------------------------------------------------------------------------------|
| `192.100.200.0/26`    | сеть HQ-CLI                                                                            |
| `192.100.20.0/28`     | сеть филиала, где BR-CLI                                                               |
| `rw`                  | чтение и запись                                                                        |
| `sync`                | подтверждать запись только после фактической записи на диск                            |
| `no_subtree_check`    | не проверять принадлежность файла дереву — быстрее и без проблем при переименовании     |
| `no_root_squash`      | не понижать права root с клиента                                                       |
| `fsid=1`              | **обязательно для FAT32** — у неё нет UUID, который NFS требует для идентификации       |

Между адресом сети и скобкой с опциями **не должно быть пробела**: пробел означает «всем, с настройками по умолчанию».

> Ошибка `exportfs: requires fsid=` появляется именно из-за FAT32. Без этого параметра экспорта не будет, а клиент получит `access denied by server`, что наводит на мысль о сети, хотя дело в файловой системе.

Сеть серверов `192.100.100.0/25` в экспорт **не включается** — задание требует доступ исключительно для сетей клиентов.

### 13.2. Клиенты

**Машины: HQ-CLI (107) и BR-CLI (110)**

```bash
apt-get install -y nfs-clients nfs-utils

# сначала проверить, что сервер виден
ping -c2 192.100.100.2
showmount -e 192.100.100.2

# ручное монтирование как проверка
mkdir -p /srv/share
mount -t nfs 192.100.100.2:/storage/share /srv/share
touch /srv/share/test-from-cli
ls -l /srv/share
umount /srv/share

# автомонтирование
echo '192.100.100.2:/storage/share /srv/share nfs defaults,_netdev,x-systemd.automount 0 0' >> /etc/fstab
systemctl daemon-reload
mount -a
df -h /srv/share
```

| Опция                     | Назначение                                                                           |
|---------------------------|--------------------------------------------------------------------------------------|
| `_netdev`                 | дождаться готовности сети; без неё загрузка может зависнуть на монтировании           |
| `x-systemd.automount`     | монтировать по первому обращению, а не при загрузке                                   |
| `systemctl daemon-reload` | systemd генерирует юниты монтирования из fstab, после правки их нужно пересоздать     |

### Проверка задания 13

```bash
# на сервере
exportfs -v                 # две строки с rw и fsid=1

# на клиентах после перезагрузки
ls /srv/share
touch /srv/share/from-hq    # на HQ-CLI
ls /srv/share               # на BR-CLI — файл виден
```
