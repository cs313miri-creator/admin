# Задание 7. Динамическая маршрутизация OSPF

**Машины:** HQ-RTR, BR-RTR

> **Контекст стенда** (нужен, чтобы команды ниже были корректны)
>
> Proxmox VE. Маршрутизаторы — **Eltex vESR 1.18**, остальное — **Альт Линукс**.
> Порты роутеров сдвинуты относительно топологии задания: **`gi1/0/2` — к ISP**, **`gi1/0/3` — внутрь офиса**
> (`net0`→`gi1/0/1` не используется, `net1`→`gi1/0/2`, `net2`→`gi1/0/3`).
> На vESR: применение — `do commit`, затем `do confirm`; на каждом интерфейсе и туннеле — `ip firewall disable`;
> удаление — повтор строки целиком с `no`. Просмотр: `show ip interfaces`, `show int status`, `show ip route`.
> В Альт: сеть в `/etc/net/ifaces/<iface>/`, применение `systemctl restart network`, пакеты через `apt-get`.
>
> Адресация: ISP `172.16.1.1/28` и `172.16.2.1/28` · HQ-RTR `172.16.1.2/28`, `192.100.100.1/25`, `192.100.200.1/26`, `192.100.30.1/29`
> · BR-RTR `172.16.2.2/28`, `192.100.20.1/28` · туннель `10.10.10.1/30` ↔ `10.10.10.2/30`
> · HQ-SRV `192.100.100.2` · HQ-CLI `192.100.200.2` · BR-SRV `192.100.20.2` · BR-CLI `192.100.20.3`
>
> Полный контекст — в [README](../README.md).

---

> **Из задания.** Сети одного офиса должны быть доступны из другого. Разрешите протокол только на интерфейсах туннеля. Маршрутизаторы должны делиться маршрутами только друг с другом. Используйте аутентификацию OSPF с паролем `P@ssw0rd`.

Требование «только в туннеле» выполняется так: все внутренние сети перечисляются через `network` внутри области, а команда `ip ospf` включается **только на туннеле**. Тогда маршруты передаются, а Hello-пакеты в пользовательские сети не рассылаются.

### 7.1. HQ-RTR

```
configure

router ospf 1
  router-id 1.1.1.1
  area 0.0.0.0
    network 10.10.10.0/30
    network 192.100.100.0/25
    network 192.100.200.0/26
    network 192.100.30.0/29
    enable
    exit
  enable
  exit

tunnel gre 1
  ip ospf instance 1
  ip ospf area 0.0.0.0
  ip ospf authentication key ascii-text P@ssw0rd
  ip ospf network point-to-point
  ip ospf neighbor 2.2.2.2
  ip ospf
  exit

do commit
do confirm
```

### 7.2. BR-RTR

```
configure

router ospf 1
  router-id 2.2.2.2
  area 0.0.0.0
    network 10.10.10.0/30
    network 192.100.20.0/28
    enable
    exit
  enable
  exit

tunnel gre 1
  ip ospf instance 1
  ip ospf area 0.0.0.0
  ip ospf authentication key ascii-text P@ssw0rd
  ip ospf network point-to-point
  ip ospf neighbor 1.1.1.1
  ip ospf
  exit

do commit
do confirm
```

| Команда                                        | Что делает                                                                 |
|------------------------------------------------|----------------------------------------------------------------------------|
| `router ospf 1`                                | создать процесс OSPF                                                       |
| `router-id 1.1.1.1`                            | уникальное имя роутера в формате IP-адреса                                 |
| `area 0.0.0.0`                                 | магистральная область                                                      |
| `network 192.100.100.0/25`                     | объявить сеть соседу                                                       |
| `enable` (дважды)                              | включить область и сам процесс — верхний забывают постоянно                 |
| `ip ospf authentication key ascii-text ...`    | пароль соседства, одинаковый на обоих роутерах                             |
| `ip ospf network point-to-point`               | в туннеле два участника, выборы DR/BDR не нужны                            |
| `ip ospf neighbor`                             | явно указать router-id соседа                                              |
| `ip ospf`                                      | включить OSPF на интерфейсе — **только на туннеле**                        |

Сети провайдера `172.16.1.0/28` и `172.16.2.0/28` в OSPF **не объявляются**: это не наши сети, и их объявление может увести интернет-трафик через туннель в чужой офис.

Если форма аутентификации не подошла, посмотри `ip ospf authentication ?`. Встречаются варианты `ip ospf authentication-key P@ssw0rd`, `ip ospf authentication key-id 1 key P@ssw0rd`. Главное — одинаково с обеих сторон.

### Проверка задания 7

```
show ip ospf neighbors     # сосед в состоянии Full
show ip route ospf         # сети чужого офиса через 10.10.10.x
```

```bash
# с HQ-SRV
ping -c3 192.100.20.2      # BR-SRV
```

Состояния соседства и что они значат:

| Состояние          | Причина                                                        |
|--------------------|----------------------------------------------------------------|
| пусто              | Hello не доходят: туннель не работает или `ip ospf` не включён  |
| Init / 2-Way       | не совпал пароль или тип аутентификации                        |
| ExStart / Exchange | разный MTU на концах туннеля — добавь `ip mtu 1400` с обеих сторон |
| Full               | всё в порядке                                                  |
