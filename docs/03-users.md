# Задание 3. Локальные учётные записи

**Машины:** HQ-SRV, BR-SRV, HQ-RTR, BR-RTR

> **Контекст стенда** (нужен, чтобы команды ниже были корректны)
>
> Proxmox VE. Маршрутизаторы — **Eltex vESR 1.18**, остальное — **Альт Линукс**.
> Порты роутеров сдвинуты относительно топологии задания: **`gi1/0/2` — к ISP**, **`gi1/0/3` — внутрь офиса**
> (`net0`→`gi1/0/1` не используется, `net1`→`gi1/0/2`, `net2`→`gi1/0/3`).
> На vESR: применение — `do commit`, затем `do confirm`; на каждом интерфейсе и туннеле — `ip firewall disable`;
> удаление — повтор строки целиком с `no`. Просмотр: `show ip interfaces`, `show int status`, `show ip route`.
> В Альт: сеть в `/etc/net/ifaces/<iface>/`, применение `systemctl restart network`, пакеты через `apt-get`.
>
> Адресация: ISP `172.16.1.1/28` и `172.16.2.1/28` · HQ-RTR `172.16.1.2/28`, `192.100.100.1/25`, `192.100.200.1/26`, `192.100.30.1/29`
> · BR-RTR `172.16.2.2/28`, `192.100.20.1/28` · туннель `10.10.10.1/30` ↔ `10.10.10.2/30`
> · HQ-SRV `192.100.100.2` · HQ-CLI `192.100.200.2` · BR-SRV `192.100.20.2` · BR-CLI `192.100.20.3`
>
> Полный контекст — в [README](../README.md).

---

> **Из задания.** На HQ-SRV и BR-SRV создайте пользователя `sshcli` с паролем `P@ssw0rd` и идентификатором `2525`, с правом запускать sudo без ввода пароля. На HQ-RTR и BR-RTR создайте пользователя `admineco` с паролем `P@ssw0rd`.

### 3.1. Пользователь на серверах

**Машины: HQ-SRV (105) и BR-SRV (106), команды одинаковые**

```bash
useradd -u 2525 -m -s /bin/bash sshcli
echo "sshcli:P@ssw0rd" | chpasswd

echo "sshcli ALL=(ALL) NOPASSWD: ALL" > /etc/sudoers.d/sshcli
chmod 440 /etc/sudoers.d/sshcli
visudo -c
```

| Параметр               | Назначение                                                                  |
|------------------------|-----------------------------------------------------------------------------|
| `-u 2525`              | задать UID явно; занятость проверяется командой `getent passwd 2525`        |
| `-m`                   | создать домашний каталог                                                    |
| `-s /bin/bash`         | оболочка по умолчанию                                                       |
| `ALL=(ALL)`            | на любом хосте, от имени любого пользователя                                |
| `NOPASSWD:`            | не спрашивать пароль — это и требует задание                                |
| `chmod 440`            | sudo игнорирует файл с другими правами                                      |
| `visudo -c`            | проверить синтаксис всех файлов sudoers                                     |

UID задан числом не случайно: в задании 13 появится NFS, а он передаёт по сети числовые идентификаторы, а не имена. При разных UID на сервере и клиенте права на файлы не совпадут.

Альтернативный способ, принятый в Альт, — через группу `wheel`:

```bash
# раскомментировать строку WHEEL_USERS ALL=(ALL:ALL) NOPASSWD: ALL
visudo
gpasswd -a sshcli wheel
```

Он тоже засчитывается, но даёт права всем членам группы, а не одному пользователю.

### 3.2. Пользователь на маршрутизаторах

**Машины: HQ-RTR (108) и BR-RTR (109)**

```
configure

username admineco
  password P@ssw0rd
  privilege 15
  exit

do commit
do confirm
```

`privilege 15` — максимальный уровень, полный доступ включая режим конфигурации. Если прошивка эту команду не принимает, посмотри доступное через `?` внутри `username admineco` — встречается форма `role admin`.

### Проверка задания 3

```bash
# на серверах
id sshcli                       # uid=2525(sshcli)
su - sshcli -c "sudo -n id"     # uid=0(root) без запроса пароля
```

```
# на маршрутизаторах
show users
```

Флаг `-n` запрещает sudo спрашивать пароль: при неверной настройке команда сразу упадёт, а не зависнет на приглашении.

> В тексте задания встречаются и `sshcli`, и `sshuser` — это опечатка составителя. Делай `sshcli`, расхождение упомяни в отчёте.
