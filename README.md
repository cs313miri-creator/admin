## Мосты Proxmox и порты vESR

Порядок адаптеров в Proxmox задаёт нумерацию портов: `net0` → `gi1/0/1`, `net1` → `gi1/0/2`, `net2` → `gi1/0/3`.

| Мост | Сегмент | Кто подключён |
|------|---------|----------------|
| `vmbr0` | Управление гипервизором / интернет | ISP `net0` (ens19). На роутерах **не используется** |
| `vmbr1` | ISP ↔ HQ-RTR, `172.16.1.0/28` | ISP `net1` (ens20), HQ-RTR `net1` = **`gi1/0/2`** |
| `vmbr2` | ISP ↔ BR-RTR, `172.16.2.0/28` | ISP `net2` (ens21), BR-RTR `net1` = **`gi1/0/2`** |
| `vmbr3` | HQ-RTR ↔ HQ-SW, VLAN 150/250/333 | HQ-RTR `net2` = **`gi1/0/3`**, HQ-SW |
| `vmbr4` | Сеть филиала, `192.100.20.0/28` | BR-RTR `net2` = **`gi1/0/3`**, BR-SRV, BR-CLI |

> **Внимание.** В топологии задания порты роутеров подписаны `gi1/0/1` и `gi1/0/2`. На этом стенде у роутеров есть лишний адаптер на `vmbr0`, он идёт первым, поэтому нумерация сдвинута на единицу. Все команды в решении даны под **реальные** порты стенда.
>
> Две машины видят друг друга, только если их адаптеры на одном мосту. Признаки неверного порта: **Link Down** в `show int status`, либо линк есть, а пинг отвечает `Destination Host Unreachable`.

## Топология

```
                  Internet
                     |
                  [ vmbr0 ]
                     |
                  +------+
                  | ISP  |  ens19 — DHCP
                  +------+
             ens20 /      \ ens21
        [vmbr1]  /          \  [vmbr2]
      172.16.1.0/28      172.16.2.0/28
             /                \
     gi1/0/2 |                 | gi1/0/2
       +---------+        +---------+
       | HQ-RTR  |========| BR-RTR  |
       +---------+  GRE   +---------+
     gi1/0/3 |   10.10.10.0/30   | gi1/0/3
        [vmbr3]                [vmbr4]
             |                    |
       +---------+           192.100.20.0/28
       | HQ-SW   |            /          \
       +---------+       +--------+  +--------+
        /       \        | BR-SRV |  | BR-CLI |
  VLAN 150   VLAN 250    +--------+  +--------+
      |           |
 +--------+  +--------+
 | HQ-SRV |  | HQ-CLI |
 +--------+  +--------+
```

Провайдер не знает внутренних сетей `192.100.x.x`, поэтому офисы соединяются **GRE-туннелем**, внутри туннеля работает **OSPF**, а выход в интернет обеспечивает **NAT**. Это задания 6, 7 и 8.

### Как получены маски

Размер сети задан **числом адресов**, а не узлов — прибавлять двойку не надо, нужен префикс, при котором `2^(32−префикс)` равно заданному числу.

| Сеть | Формулировка задания | Расчёт | Итог |
|------|----------------------|--------|------|
| VLAN 150 | из `192.100.100.0/24`, не более **128 адресов** | 128 = 2⁷ → 32−7 | `/25` |
| VLAN 250 | из `192.100.200.0/24`, не более **64 адресов** | 64 = 2⁶ → 32−6 | `/26` |
| VLAN 333 | из `192.100.30.0/28`, не более **8 адресов** | 8 = 2³ → 32−3 | `/29` |
| Сеть филиала | из `192.100.20.0/26`, не более **16 адресов** | 16 = 2⁴ → 32−4 | `/28` |
| GRE-туннель | диапазон `10.10.10.0/24`, маска **минимальная** | 2 узла → 4 = 2² → 32−2 | `/30` |

Стыки `172.16.1.0/28` и `172.16.2.0/28` заданы в условии напрямую.

## Особенности Eltex vESR

| Команда | Назначение |
|---------|------------|
| `configure` | войти в режим конфигурации |
| `do commit` | применить изменения |
| `do confirm` | подтвердить; без него откат примерно через 10 минут |
| `?` | показать допустимые продолжения для этой прошивки |
| `show ip interfaces` | адреса на интерфейсах |
| `show int status` | состояние портов: Admin / Link |
| `show ip route` | таблица маршрутизации |
| `show running-config` | вся конфигурация |

Три вещи, из-за которых чаще всего ничего не работает:

1. **Двухфазное применение.** Команды лежат в кандидатной конфигурации и не действуют до `do commit`. Индикатор — приглашение: после `hostname BR-RTR` оно остаётся `vesr(config)#` и меняется только после применения.
2. **vESR — межсетевой экран.** Транзит по умолчанию отбрасывается. В решении на каждом интерфейсе и туннеле стоит `ip firewall disable`. Если команды нет — настраиваются зоны (`security zone`, `security zone-pair`).
3. **Удаление требует значения.** `no ip address 172.16.1.2/28`, а не просто `no ip address` — иначе `Incompleted command`.

## Особенности Альт Линукс

Сеть описывается папками в `/etc/net/ifaces/<интерфейс>/` — система **etcnet**:
`options` (тип и способ адресации), `ipv4address` (адрес с префиксом), `ipv4route` (`default via ...`), `resolv.conf` (DNS).
Применение — `systemctl restart network`.

- Команда называется **`apt-get`**, не `apt`.
- Редактора **`nano` может не быть** — используется `sed -i` и `cat > файл <<'EOF'`, либо `vi`.
- На **рабочих станциях** сначала выключается NetworkManager, иначе etcnet не применится.
- `/etc/resolv.conf` **генерируется** — править нужно `/etc/net/ifaces/<iface>/resolv.conf`.
- Имена интерфейсов проверяются через `ip -br link`.

## Как пользоваться с ИИ-помощником

Каждый файл в `docs/` **самодостаточен**: вверху повторён контекст стенда — порты, адреса, особенности vESR и Альт. Помощнику достаточно одного файла, чтобы давать корректные команды.

**Давай raw-ссылку на конкретное задание**, а не на весь репозиторий — так помощник прочитает файл целиком, не упираясь в лимит:

```
https://raw.githubusercontent.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ/main/docs/07-ospf.md
```

Готовая формулировка запроса:

```
Вот решение задания по настройке сети:
https://raw.githubusercontent.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ/main/docs/07-ospf.md

Контекст стенда указан в начале файла — порты роутеров и адреса бери оттуда,
не из общих примеров.

Проблема: выполняю команду <какую>, получаю <текст ошибки дословно>.
Вывод show ip ospf neighbors:
<вставить вывод>

Что проверить и какие команды выполнить?
```

Что важно передать помощнику, чтобы он не навредил:

- порты роутеров — **`gi1/0/2`** к ISP и **`gi1/0/3`** внутрь, а не `gi1/0/1`/`gi1/0/2` как в типовых примерах;
- на vESR обязателен **`do commit`** и **`do confirm`**, иначе настройки откатятся;
- адреса — из таблицы выше, диапазон `192.100.x.x`, а не `192.168.x.x`.

Если помощник предлагает команды с другими портами или адресами — он работает по общему шаблону, а не по этому стенду. Укажи ему на блок контекста в начале файла.

**Текст ошибки передавай дословно.** В [docs/troubleshooting.md](docs/troubleshooting.md) собраны сообщения vESR и Альт с расшифровкой — часто ответ находится там без всякого помощника.
